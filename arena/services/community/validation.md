# Community HTTP and XMPP validation

Native legacy registration/login and Launcher HTTPS login were verified before this refactor. Launcher registration was not, and the boolean `createUser` response it shipped with never completed on the retail client; the hosted deployment verified the `["0", username]` item pair on 2026-09-16, with registration continuing into SNAP auto-login, profile synchronisation and ranking queries. `arena/games/ashen/tests/test_community.py` and `arena/services/community/tests/test_community.py`, `test_profiles.py`, `test_tls.py` and ranking/achievement suites exercise live HTTP/XMPP framing, session policy, bad credentials and TLS listeners. The refactor changes locations and startup ownership; final results are recorded in [refactor validation](../../../docs/refactor-validation.md).
